# Project Summary — Full Repo Scan

Scope of review coverage: **all 19 comments are in `scripts/`** (build-time / CI tooling). No application source, tests, or CI config received comments, so this summary is about the developer tooling layer, not the shipped product code.

### Top Issues

1. **Silent failure is the default error mode across all four scripts.** Nearly every comment describes a path where bad input or an environment problem produces a plausible-looking success instead of an error. Unknown `--flags` are stripped and ignored (`scripts/subset-font.ts`); an unmatched font name selects nothing and continues; paths without a matchable `d` attribute are dropped (`scripts/icons.ts`); `readdirSync`/`readFileSync` failures in `scripts/check-budgets.ts` and unguarded writes in `scripts/icons.ts` escape as raw stack traces. Net effect: the tooling can emit corrupt assets or a false budget pass while exiting 0.

2. **Verbatim argument-parsing duplication with the same defect** — `rootFrom` in `scripts/icons.ts` and `scripts/check-budgets.ts` is copy-pasted, and in both a bare `--root` yields `undefined` (silent fallback) while `--root --check` swallows the next flag as a path. Any fix must land in two places today.

3. **Non-atomic writes to cached/downloaded artifacts** (`scripts/subset-font.ts`): the TTF is written straight to its cache path, so an interrupted or disk-full write leaves a truncated file that `existsSync` permanently trusts. There is no temp-file + rename, and no checksum — downloaded bytes are trusted on an HTTP 200 alone, then shipped as a web asset.

4. **Generated TypeScript is built by raw string interpolation** (`scripts/icons.ts`): `name` and path data are spliced into a single-quoted literal with no escaping, so a `'`, `\`, or newline silently corrupts the committed module rather than failing generation. Combined with issue 1, this is a silent-corruption vector on a checked-in file.

5. **The budget gate can be bypassed by symlinks and is paying for files it discards** (`scripts/check-budgets.ts`): `Dirent.isFile()`/`isDirectory()` are both false for symlinks, so a symlinked file or whole subtree escapes the budget entirely — a correctness gap in the check, not just a perf issue. Separately, `collectSourceFiles` reads every file under vendored trees (`apps/web/components/ui`, `packages/dsl/src`) that `checkFiles` then throws away.

6. **`scripts/icon-names.ts` is pinned at exactly its hard ceiling** — 150 entries against `expect(ICON_NAMES.length).toBeLessThanOrEqual(150)` in `check-icons.test.ts`. The file's own header promises adding a name is "one run of `bun run icons` away," which is now false: the next addition fails the suite.

7. **A design rationale in `scripts/icon-names.ts` contradicts the implementation.** The comment justifies the size cap by first-paint cost, but the dataset is only reachable via dynamic import in `apps/web/lib/icon-set.ts` (enforced by the lazy-loading test), so it never participates in first paint. The real cost is download/parse on picker open — a different budget than the one documented.

8. **Fragile attribute parsing in `scripts/icons.ts`.** Double-quote-only extraction, full-value guards missing on `(?!none)` so `noneX`, `None`, and `none ` are misclassified as unsupported styles, and `stroke="none" fill="currentColor"` paths are dropped as invisible even though they are visible filled geometry. Single-quoted source SVGs degrade silently.

### Module Hotspots

- **`scripts/icons.ts` — 7 comments**, the densest file and the only one mixing correctness, escaping, error handling, perf, and path-resolution issues. Treat as the highest-risk file in the scan.
- **`scripts/subset-font.ts` — 5 comments**, clustered on the download → verify → cache → subset pipeline; every stage has an integrity or error-reporting gap.
- **`scripts/check-budgets.ts` — 4 comments**, all in the walk/entry-point layer (`collectSourceFiles`, `Dirent`, `readdirSync` error handling, `argv[1]` vs `import.meta.url` realpath comparison under symlinks or macOS `/tmp` vs `/private/tmp`).
- **`scripts/icon-names.ts` — 2 comments**, but both are structural (hard cap reached, rationale wrong).
- **`scripts/` overall: 19/19 comments.** There is no reviewed code outside this directory — flag as a coverage gap, not a quality signal.

### Cross-Cutting Concerns

- **Inconsistent error taxonomy.** Only `ENOENT` should mean "file missing," but `scripts/icons.ts` catches all read failures and reports "is missing," sending readers to `bun run icons`, which cannot fix `EACCES`/`EISDIR`/I/O errors. The same conflation appears when `readdirSync` throws in `scripts/check-budgets.ts`: an infrastructure fault is indistinguishable from a budget verdict.
- **Unhandled rejections / unguarded top-level execution.** `await main()` in `scripts/subset-font.ts` has no catch; `scripts/check-budgets.ts` guards its entry point with a `resolve(process.argv[1])` comparison that fails under symlinks and macOS path aliasing, so the gate silently doesn't run. Both contradict the otherwise user-friendly CLI tone of these scripts.
- **Loose, substring-based flag and name matching** (`'mono'` → both Geist weights, `'balsamiq'` → all four) in `scripts/subset-font.ts`, plus flag-stripping that defeats the safety intent of `--offline`. This is the same class as the `--root` parsing bug in the other two files: permissive matching where exactness is the whole point.
- **Silent-skip patterns replace loud failure** in every script: unmatched `<path>`, undownloadable weights, symlinked entries, unknown flags. There is no shared "reject or report" convention.
- **Redundant per-item work in generation loops**: `outlineDirectory()` re-runs `require.resolve` + `existsSync` for all 150+ icons because `readIcon` calls it per name, and it hard-codes the `../icons/icons/outline` sibling layout.
- **Tooling invariants live in tests only, not in the scripts**: the 150-icon cap is asserted in `scripts/check-icons.test.ts` while `scripts/icon-names.ts` documents a policy that no longer holds.

### Quick Wins

- **Wrap the entry points.** `main().catch(err => { …; process.exit(1) })` in `scripts/subset-font.ts` and `scripts/check-budgets.ts`; translate known errors into the existing user-facing messages. Small diff, removes all raw-stack-trace failures.
- **Extract one shared `parseArgs`/`rootFrom` helper** and have `scripts/icons.ts` and `scripts/check-budgets.ts` import it — fixes the duplicate bug and the `--root --check` swallowing in one change.
- **`mkdirSync(dirname(target), { recursive: true })`** before the `writeFileSync` in `scripts/icons.ts`; then try/catch the write and render to emit a message instead of a trace.
- **Narrow the catch in `scripts/icons.ts`** to `err.code === 'ENOENT'`; rethrow everything else.
- **Hoist the vendored-directory filter** in `scripts/check-budgets.ts` so `collectSourceFiles` skips `apps/web/components/ui` and `packages/dsl/src` before reading, rather than reading then discarding.
- **Resolve the outline directory once** in `scripts/icons.ts` and pass it into `readIcon`, removing 150+ redundant `require.resolve`/`existsSync` calls.
- **Tighten matching:** exact weight comparison in `WEIGHTS` lookup (`scripts/subset-font.ts`), reject unknown `--flags` outright, and anchor the style guard to the full attribute value (`none` only) in `scripts/icons.ts`.
- **Escape generated literals** in `scripts/icons.ts` (`JSON.stringify` for the string literal) — one-line change that closes the committed-module corruption path.
- **Raise or remove the 150 cap and correct the comment** in `scripts/icon-names.ts` so the documented workflow ("one run of `bun run icons`") matches the assertion in `check-icons.test.ts`.
- **Use `lstatSync`/`statSync` instead of `Dirent.isFile()`** in `scripts/check-budgets.ts` to stop symlinked files and subtrees from escaping the budget.
