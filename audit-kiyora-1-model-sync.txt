──────── Project Summary ────────

### Top Issues

1. **Conflict resolution is not atomic — a mid-sequence failure leaves the local board swapped with a stale record.** In `packages/sync/src/conflict.ts`, `replaceLocal` runs inside the same `try` as `adoptLocal`, `setRecord`, `cache.clear` and `setState`. If `setRecord` throws after `replaceLocal` succeeds, the board is already replaced while `record()` still describes the pre-resolution state. Every step after the destructive write needs to be independently recoverable (or the destructive write must be last / rolled back).

2. **A stale cached copy can be applied over the user's local edits.** Two related defects in `conflict.ts`: (a) on a refused write with no payload, the previously cached `copy` is kept while `conflict` advances to the new revision, so `takeTheirs`/`duplicateMine` take the `readyCopy()` shortcut and `applyRemote` an out-of-date board; (b) `opening` only guards re-entry to `open()`, not interleaving with resolutions, so a resolution racing an in-flight load sees `readyCopy() === null` and silently bails. Combined, the "never accept a stale copy" invariant is asserted but not enforced.

3. **The wire/trust boundary is unvalidated in both directions.** `packages/sync/src/transport.ts` declares `DownloadedBoard.payload: Board` by cast, with nothing requiring adapters to parse untrusted JSON first, so a malformed response reaches the reconciler as a valid `Board`. Mirroring this, `packages/sync/src/protocol.ts` trusts caller-supplied `write.bytes` (a negative or `NaN` value bypasses the `> LIMIT` check entirely) and trusts `write.payloadHash` as proof of payload identity without ever hashing the payload — so a stale or forged hash is accepted as an idempotent replay.

4. **Failures are swallowed at exactly the points where state must be persisted.** In `conflict.ts`, `duplicateLocal` errors collapse to `null` (caller gets `false`, user retries blind, a storage fault is indistinguishable from "nothing to do"), and a rejected `saveRecordFor` leaves the duplicate uploaded but permanently recorded as unlinked — it will be re-offered for linking every session. `cache.write` in `open()` is unguarded where `remember()` guards the same operation, so a cache fault is misreported as `offline` after a successful download.

5. **A bare `catch` in `packages/sync/src/reconcile.ts` classifies every thrown error as `{ reason: 'network' }`.** Programming errors (serialization, `saveRecord` failures) and auth errors surfaced as exceptions are therefore treated as transient and retried forever, and the surface shows a connectivity message for a client bug.

6. **Queue coalescing discards the queued operation's intent.** `queued` is a boolean in `reconcile.ts`, so a `link()` issued during an in-flight upload is later replayed as `reconcile()` → `start(record.revision)` instead of a `baseRevision`-checked link. Relatedly, `SyncRecord.pending` is documented as "the local copy holds a change its upload has not accepted" but a refused write sets `pending: false` — the exact case the field exists to describe.

7. **The same decision is re-implemented in several places and already reports different answers.** `reconcile.ts` returns `baseRevision ?? 0` for `local` in one conflict path while `initial()`, `reconcile()` and `markPending()` return `record.revision ?? 0`; `markPending` duplicates the ordered `blocked → !linked → !signedIn → conflict` guard chain from `reconcile`; `takeTheirs` and `duplicateMine` share a verbatim copy of the `readyCopy()`/`await open()`/early-return lookup. `conflict.ts` also passes inconsistent `local`/`remote` arguments to `conflictState` on a second refusal, which the UI renders directly.

8. **`duplicateMine` commits side effects before it knows the resolution can succeed** (`conflict.ts`): the duplicate is created (and possibly uploaded) before the resolution can fail, yet the function returns `false` on upload rejection and also returns `false` after a *successful* upload when no remote copy loads. The caller cannot distinguish these, and one of them is a success.

9. **`sameCopy` deep-serialises an entire `Board` on every `show()` call** (`conflict.ts`). Since `open()` runs during editing, this cost recurs on large boards just to decide whether to publish. Serialise a cheap discriminator (revision/updatedAt/hash) instead.

### Module Hotspots

- `packages/sync/src/conflict.ts` — 10 of 21 comments, and the highest-severity cluster: atomicity, stale-copy application, swallowed storage failures, and duplicated resolution logic all land in this one file. This is the module to prioritise for refactor and for state-machine tests.
- `packages/sync/src/reconcile.ts` — 5 comments, all on the same theme: error classification, queue intent, and inconsistent conflict reporting.
- `packages/sync/src/protocol.ts` — 3 comments, all about trusting caller-supplied input (`bytes`, `payloadHash`) and about malformed payloads being reported as `reason: 'version'`.
- `packages/sync/src/transport.ts` — 3 comments, all contract-documentation/validation gaps on the port interface.

The whole scan is confined to `packages/sync/src`; no other package surfaced a comment.

### Cross-Cutting Concerns

- **Swallowed or misclassified errors at persistence boundaries.** `duplicateLocal` → `null`, `saveRecordFor` rejection ignored, unguarded `cache.write`, and the bare `catch` in `reconcile` all convert a hard fault into either a silent no-op or a retryable "network" state. Representative paths: `packages/sync/src/conflict.ts`, `packages/sync/src/reconcile.ts`.
- **Untrusted data crossing into typed domain models without validation.** `DownloadedBoard.payload` (`transport.ts`), `SyncWrite.bytes` and `write.payloadHash` (`protocol.ts`). No file in this set parses or rejects malformed input before it reaches the reconciler.
- **Duplicated control flow that is already drifting.** Three instances: the `readyCopy()`-else-`open()` lookup (`takeTheirs`/`duplicateMine`), the guard chain (`reconcile`/`markPending`), and the `local`/`remote` revision reporting across four conflict-producing sites. Each pair has diverged or will.
- **Undocumented port contracts.** `SyncTransport`'s methods carry no JSDoc, so invariants the reconciler depends on — `download` resolves `null` for absence rather than throwing, `list` is unordered and list-tolerant, `updatedAt` is display-only and staleness must be decided from `revision` per ADR 0011 — exist only in the reconciler's assumptions.

### Quick Wins

- Add JSDoc to each `SyncTransport` member in `transport.ts` stating the absence/throw, ordering, and `updatedAt`-is-display-only invariants, plus an explicit requirement that adapters validate wire JSON before casting to `Board`.
- Harden the size guard in `protocol.ts`: `Number.isFinite(write.bytes) && write.bytes >= 0 && write.bytes <= LIMIT`, so `NaN`/negatives cannot bypass it.
- In `conflict.ts`, move the `replaceLocal` call out of the shared `try` (or make post-swap steps non-throwing), so a `setRecord` failure cannot leave a swapped board with a stale record.
- Extract `ensureReadyCopy(): Promise<ReadyCopy | null>` in `conflict.ts` and use it in both `takeTheirs` and `duplicateMine` — removes the verbatim duplicate and gives staleness a single place to be enforced.
- Extract a shared `reportBlockedState(...)` helper used by `reconcile()` and `markPending()` so the guard order is defined once.
- Wrap `cache.write` in `open()` the same way `remember()` does, so a cache failure no longer surfaces as `offline` after a successful download.
- Normalise the `local` argument on every `status: 'conflict'` path to `record.revision ?? 0` (fix the `baseRevision ?? 0` site and the second-refusal `conflictState` call together — same one-line class of fix).
- Replace the `sameCopy` full-`Board` serialisation with a cheap identity check (revision/`updatedAt`/cached hash).
- Distinct `reason` for malformed payloads in `protocol.ts` instead of reusing `'version'`, so callers stop treating corruption as a version mismatch.
