# Project Summary — Full-Repo Scan

Scope: 84 comments across 23 files, overwhelmingly concentrated in `apps/web/lib` (auth, db, storage/sync adapters). The findings cluster into a small number of root causes rather than isolated bugs.

### Top Issues

1. **Foreign platform errors escape adapter boundaries everywhere.** This is the single most repeated finding: `DOMException`, `TypeError`, `ReferenceError`, `SyntaxError` and `ZodError` propagate untranslated into UI code that renders `error.message` to the person. Representative sites: `apps/web/lib/board-file.ts` (`file.text()`, `serializeBoard`/`createObjectURL` throwing synchronously out of a `void` function), `apps/web/lib/board-png.ts` (`drawImage`, `toBlob` `SecurityError`), `apps/web/lib/image-import.ts` (`slice().arrayBuffer()`, `toDataURL`), `apps/web/lib/board-channel.ts` (`BroadcastChannel` construction → bare `ReferenceError`), `apps/web/lib/remote-board.ts`, `apps/web/lib/share.ts`, `apps/web/lib/sync/transport.ts`, `apps/web/lib/new-board.ts` (`crypto.randomUUID` undefined outside secure contexts), `apps/web/lib/auth/session.ts`. The fix is uniform: a typed refusal type per adapter, converted at the boundary.

2. **Storage faults are silently dropped, creating invisible data-loss paths.** `apps/web/lib/board-storage.ts` returns a durable localStorage store while `fault` still holds the IndexedDB failure (contradicting its own documented invariant); `apps/web/lib/board-import.ts` discards `openStore()`'s fault so an import into the volatile in-memory store "succeeds" and vanishes on reload; `apps/web/lib/use-board-route.ts` drops `openFault` in one of three near-identical `setState` branches and swallows `library.setSync` errors in `recordSync`. Combined effect: the person is told a board is saved when it is not.

3. **Auth environment/security configuration is under-validated.** `apps/web/lib/auth/env.ts` hardcodes `localhost`/`127.0.0.1`/`*.localhost` into `trustedOrigins` in production, accepts non-HTTP(S) values whose `origin` becomes `'null'`, and accepts placeholder `BETTER_AUTH_SECRET` values. `apps/web/lib/auth/server.ts` gates password auth only on `AUTH_DEV_CREDENTIALS`, relying on `NODE_ENV === 'production'` (unset `NODE_ENV` = dev credentials live), and registers both OAuth providers unconditionally. The boot error message also names 3 of the 7 required variables, so a correct fix produces a second error.

4. **Database schema lacks several integrity constraints.** `apps/web/lib/db/schema.ts`: case-sensitive `email` uniqueness (`Alice@x.com` vs `alice@x.com` become two accounts), no `uniqueIndex` on `(providerId, accountId)` required by Better Auth's reference schema, `timestamp()` without `{ withTimezone: true }` making `expires_at` comparisons timezone-dependent, and no `(owner_id, updated_at)` composite index for the listing query.

5. **Check-then-act races and coarse locking in the persistence layer.** `apps/web/lib/db/board-store.ts` `create` races on concurrent first writes (`FOR UPDATE` cannot lock a nonexistent row → PK violation escaping as a non-`BoardWriteRefusal`); `apps/web/lib/remote-board.ts` `holds`→`create` has no mutual exclusion and commits bytes separately from `setSync`, leaving orphaned boards on partial failure; `apps/web/lib/db/index.ts` caches the pool on `globalThis` regardless of `databaseUrl` and pins `max: 1`, serialising all DB work and creating deadlock exposure for any nested transaction.

6. **Unbounded queries on the hot listing path.** `apps/web/lib/db/board-store.ts` `listBoards` has no `LIMIT` and sorts in DB memory; `apps/web/lib/db/share-store.ts` and `apps/web/lib/db/board-store.ts` also differ in their non-enumeration stance (`forbidden` vs `null`/`absent`).

7. **Browser-only modules carry no `'use client'` boundary.** `apps/web/lib/auth/client.ts` (builds a React-hooks auth client at import time), `apps/web/lib/share.ts` (`window` in `absoluteShareUrl`), `apps/web/lib/text-measurer.ts` (despite a comment promising SSR safety), and `apps/web/lib/board-channel.ts` are kept out of the RSC graph only by consumer discipline.

8. **Cross-file duplication of policy that must stay in sync.** `readAuthEnv()` + `getDatabase()` blocks copy-pasted three times in `apps/web/lib/db/board-store.ts`; `copyTitle` duplicated between `apps/web/lib/use-board-route.ts` and `packages/editor/src/persistence/library.ts`; `fontFamilyOf` re-implemented in `apps/web/lib/text-measurer.ts` instead of using `@kiyora/model`; API route paths hardcoded in `apps/web/lib/share.ts` and `apps/web/lib/sync/transport.ts`; the panel-crash key literal duplicated into two e2e specs.

9. **Fail-safe `catch`es with no signal.** `apps/web/lib/board-png.ts` (font fetch failure → silently wrong raster), `apps/web/lib/text-measurer.ts` (measurement failure → returns `0`, wrong wrapping with correct painting), `apps/web/lib/use-board-route.ts` (`recordSync`), `apps/web/lib/panel-crash.ts` (undocumented fail-safe). These violate the project's "a catch must surface something" rule.

10. **Sticky failure caches.** `apps/web/lib/icon-set.ts` `pending ??=` caches a rejected promise permanently (one flaky chunk load breaks icons for the session); `apps/web/lib/text-measurer.ts` writes `null` back to the context field, so the failure path is never memoised and every `measure()` allocates a canvas.

### Module Hotspots

- **`apps/web/lib/db/`** — highest density by far: `board-store.ts`, `share-store.ts`, `schema.ts`, `migrate-check.ts`, `index.ts` account for ~19 comments spanning security, correctness, migrations, and performance. This is the layer that most needs a design pass.
- **`apps/web/lib/` (root adapters)** — `board-storage.ts`, `board-import.ts`, `remote-board.ts`, `board-file.ts`, `board-png.ts`, `image-import.ts`, `sync/transport.ts`, `share.ts`, `use-board-route.ts`: 9 files, all reporting the same boundary-conversion defect.
- **`apps/web/lib/auth/`** — 4 files; small in line count but every comment is security-relevant (`env.ts`, `server.ts`, `client.ts`, `session.ts`).
- **`apps/web/lib/db/migrate-check.ts` alone** — 5 comments (count-only guard, `finally` swallowing the real error, unvalidated journal JSON, `cwd`-relative path breaking `--output standalone`, client constructed outside `try`), i.e. the boot-check itself fails opaquely.

### Cross-Cutting Concerns

- **Adapter boundary contract is not enforced anywhere.** The same defect appears in 10+ files: platform/driver errors are not converted to the module's refusal type. See `board-file.ts`, `board-png.ts`, `image-import.ts`, `remote-board.ts`, `sync/transport.ts`, `share.ts`. Fixing this once (a shared "convert foreign error" helper or a lint-enforced boundary pattern) retires the majority of the comment set.
- **Failures are reported to the person as "not found" or "offline".** `use-board-route.ts` maps storage I/O errors to `status: 'missing'`; `sync/transport.ts` maps 5xx/429 to `network`, which the reconciler then retries forever. Any storage or server fault currently reads as user-side breakage.
- **Partial writes / non-atomic persistence.** `remote-board.ts` (`create` then `setSync`), `board-storage.ts` (settling on `request.success` rather than `transaction.complete`), `share-store.ts` (ownership check and token read as separate statements), `board-store.ts` (create race).
- **Silent degradation instead of diagnosable state.** `board-storage.ts`, `board-import.ts`, `board-png.ts`, `text-measurer.ts`, `icon-set.ts`, `panel-crash.ts`: the system keeps painting while losing fidelity, without emitting a fault.
- **Duplicated policy constants and helpers across packages.** `text-measurer.ts` vs `@kiyora/model`'s `fontFamilyOf`; `image-import.ts` exporting `IMAGE_PLACEMENT_SIDE` from `apps/web` while sibling raster constants live in `@kiyora/model`; `use-board-route.ts` vs `packages/editor` `copyTitle`; `board-store.ts` ×3 env resolution.
- **Comments that assert guarantees the code does not provide.** `board-storage.ts` doc (`a fallback that persists is not a failure`), `text-measurer.ts` (SSR safety), `use-board-route.ts` `recordSync` ("the next save writes it again"), `schema.ts` (preview_svg is server-justified markup — it is not).
