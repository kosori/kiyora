# Kiyora v1

v1 is a hand-drawn whiteboard that works with the network off: draw shapes, connect them, add text and stickies, style them, reload without losing anything, export PNG and SVG, and present slides. One board, in this browser, no account.

The diagram-code panel is **not** in v1. It is the first thing in v1.5.

**Status: v1 is done.** Every capability below is proven by the named test, the acceptance journey and the offline guard are green, and the payload, first-paint and file-size budgets pass. Where the table once named a test that was weaker than its claim, the row now names the test that asserts paint or behaviour; no row leans on a test that only counts elements.

## Definition of done

Three conditions, all mechanical.

**1. The acceptance journey passes in CI.** One Playwright test walks the whole product:

> open → draw a rectangle and an ellipse → connect them → add text and a sticky → select and move → reload, state survives → export PNG at 2× → export SVG → add two slides → present → exit

The test is `apps/web/tests/e2e/journey.spec.ts`. It runs with every non-localhost request aborted, so the offline guard is proven on the journey itself rather than beside it.

**2. Every capability below is proven by a named test.** This table is the contract. A row is done when its test exists and asserts paint or behaviour. **A capability whose test only asserts that an element exists, or counts elements, is not proven** — that is exactly how an invisible Text tool once shipped behind 2,000 green tests.

**3. Every gate is green.** `turbo run check`, `check-types`, `test`, `test:e2e`, plus the offline guard, the size budget and the payload budget.

### Where the tests attach

Two seams, and no third.

- **The app in a browser.** Every capability above is proven here. Storage faults are injected by replacing `indexedDB` or `localStorage` before the app boots, which keeps them at this seam rather than justifying a new one.
- **The packages' public entry points.** Node, importing each package's entry and nothing deeper. Only where the browser is blind or slow: the vendored parser's fixtures, paint per figure kind, geometry, snapping, history coalescing, migrations, the projector's goldens, and the keymap.

Not built: component tests, a jsdom environment, DOM mocks, or anything reaching past a public entry. The React adapter is proven through the browser. `apps/web` therefore has no unit test runner of its own.

Cross-cutting, not a capability but a gate:

| Gate | Proven by | Milestone |
| --- | --- | --- |
| Offline by construction | `apps/web/tests/e2e/offline.spec.ts` — aborts every request that is not to localhost | M1 |
| The e2e run proves which app it tested | `apps/web/tests/global-setup.ts` — asserts the served page carries the build marker | M1 |
| Payload and first-paint budget | `apps/web/tests/e2e/budget.spec.ts` | M8 |
| File size budget | `scripts/check-budgets.ts` | M0 |

## Milestones

Prefix `M`, in order. Each one ends in something observable.

| # | Milestone | Done means |
| --- | --- | --- |
| M0 | Skeleton | Repo hygiene, CI, LICENSE and notices, this doc set, `packages/dsl` ported with green tests, `check-budgets.ts` wired in |
| M1 | **Vertical slice** | One rectangle drawn end to end: `model` schema, geometry and paint → `editor` store, gestures and history → canvas host with pan, zoom, select, move, resize → autosave → the offline guard and the identity check green. The architecture is falsified here, cheaply, or it is wrong. |
| M2 | Shapes, text, stickies | The whole vocabulary, the picker, the inspector, text with the markdown subset and the edit overlay, stickies |
| M3 | Connectors | Bound and free endpoints, the three routes, independent heads, labels |
| M4 | Persistence hardening | Migrations with fixtures, the fallback chain, quarantine, recovery snapshot, fault states, cross-tab warning |
| M5 | Export | SVG projection with goldens, PNG rasterization, the options matrix, board file open and save, size caps |
| M6 | Chrome | The `?` dialog generated from the keymap, keyboard reachability, focus, reduced motion, empty state, status bar, zoom-banded grid |
| M7 | Slides and present | Deck panel, five templates, notes, present mode with the notes and timer overlay |
| M8 | Acceptance | The journey green, the budget tests green, this table complete, docs refreshed |

M1 is deliberately thin. Finishing `model` and `editor` before anything is visible would hide an architectural mistake behind weeks of work; the vertical slice surfaces it in days.
