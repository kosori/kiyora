# Kiyora v1.5

v1.5 makes the board usable for real diagram work: the code panel arrives, several shapes become one thing you can move, and the board stops being light-only. Nothing here needs a server.

**Status: cut 1 shipped in #63; cuts 2 and 3 are not started.** The draft of this document was a single ranked band of 28 rows. An audit against the code found that thirteen of those rows are new subsystems rather than extensions, that the missing half of the code panel is a **layout engine** and not a mapping, and that six statements described the target design as if it had shipped. What follows is the audited version. What left is in [Not in v1.5](#not-in-v15).

**Three cuts.** Cut 1 changes what the product is. Cuts 2 and 3 are additive and may slip without leaving v1.5 half-built. Rows inside a cut are still ranked.

## Cut 1 — the panel and the selection

### Foundations (N0)

Nothing in this milestone is visible. All of it is a prerequisite the rest of the cut would otherwise pay for three times.

| Item | Notes |
| --- | --- |
| Schema `v2` | The frame's source fields and the `group` kind, in one bump, with a committed `v1 → v2` fixture pair |
| Board file open migrates | Today `openBoardFile` validates and rejects; an old `.kyr.json` must lift, not fail |
| A size cap on open | There is none today; the whole file is read into a string |

### The panel (N1)

| Item | Notes |
| --- | --- |
| A tabbed right rail | Inspector, deck and code, one column, so the canvas keeps its width |
| The diagram-code panel | A source textarea, a diagnostic list, and `⌘/Ctrl+Enter` to apply |
| Forgiving diagnostics | A warning ignores a line, an error leaves it unparsed, and the build always continues — including for a family we cannot express, which is one diagnostic and not an empty board |
| A source on the frame | `source: { text, generatedIds, stale }`. The AST is derived at apply time and never stored |
| Apply as one gesture | Generated shapes are replaced in a single history entry; hand-added shapes inside the frame survive |
| Pending and stale | Editing the text is pending; editing a generated shape is stale; applying a stale frame asks first |

### The bridge (N2)

| Item | Notes |
| --- | --- |
| AST to shapes | The parser's AST stays its own model; the bridge maps it into the shape union |
| The vocabulary mapping | The parser's words to the board's figures, in one tested place |
| Our own layout | Deterministic, layered by `direction`, in `model`, with no dependency: the same source must always produce the same board or no golden test can exist |
| Boxes, connectors, groups | Group boxes derived, connectors bound to the nodes they join, ids remapped into the board's space |

There is no `shapes → source` serializer, and there will not be one. Source is an input; the frame keeps the text it was generated from.

## Cut 2 — the library (N4–N6)

Figure kinds are cheap: a name in `SHAPES` and one geometry entry. A kind that carries a payload is not, because it needs a schema bump, a migration fixture, a paint branch and an editing surface. This cut is mostly the second kind, so it takes one more bump to `v3`.

The order is icons, device frames, wireframe controls, images, ink, tables, charts: icons first because they carry the only budget risk, images fourth because they are the first payload-carrying kind and set the precedent the others copy, and the `v3` schema bump lands with images.

| Item | Notes |
| --- | --- |
| Icon library | A committed dataset with a generator and a `--check` test, loaded lazily so it never reaches the first paint |
| Device frames | Phone, tablet, browser, window — the variants the model names and paint ignores today |
| Wireframe controls | The control shapes: button, input, slider, tabs and the rest |
| Images | PNG and JPEG, placed and resized, with the source validated as a raster payload. The SVG sanitizer refuses `<image>` and `data:` today; that changes here, deliberately |
| Freehand ink and highlighter | Pointer pressure where the hardware reports it |
| Tables | Editable cells |
| Charts | Eight kinds as editable shapes |

## Definition of done

Same three conditions as [v1](./v1.md).

**1. A second acceptance journey passes in CI.** `apps/web/tests/e2e/journey-code.spec.ts`:

> open → type source → apply → shapes appear inside the frame → edit one by hand → stale → apply again, one undo restores both the shapes and the flag → a line the parser cannot read leaves a diagnostic and the rest of the board intact → export PNG

The v1 journey stays green and unchanged. It is the regression net.

**2. Every capability below is proven by a named test** that asserts paint or behaviour. An element count proves nothing.

**3. Every gate is green**, with the budgets unchanged: `check`, `check-types`, `test`, `test:e2e`, `check-budgets`, and the payload and first-paint ceilings stay where v1 left them.

## Corrections to the draft

Recorded rather than quietly reworded.

- **"The derived box the model already supports"** — groups do not exist in the shipped union. `architecture.md` and `glossary.md` describe the target; `v1.5.md` read as if it had shipped.
- **"The flag is in the record today; this adds the UI"** — the flag is in the record and honoured nowhere. Resize, rotate, nudge and restyle never read it.
- **"The frame variants the model already names"** — named, validated, round-tripped and never painted.
- **"The bridge: AST to shapes, new work, small"** — small for the mapping. The parser carries no coordinates and the repo has no layout engine, so the missing half is layout.
- **"The build always continues"** — false today: an unsupported family returns an empty diagram and abandons the file. Fixed in N1.
- **No `shapes → source` serializer** is a position about hand edits, not about generation. v2 says so.
