# Kiyora v1.5

v1.5 makes the board usable for real diagram work: several shapes at once become one thing you can move, the code panel arrives, and the board stops being light-only. Nothing here needs a server.

This is the second priority band. It is ranked, and earlier rows are more valuable than later ones.

## Code panel and the bridge

The one genuinely hard part, and the reason the parser was ported in v1.

| Item | Notes |
| --- | --- |
| The diagram-code panel beside the canvas | `⌘/Ctrl+Enter` applies the source to a frame |
| The bridge: AST to shapes | New work, small. The parser's AST stays its own model; the bridge maps it into the board's shape union |
| The vocabulary mapping | The parser's words to the board's figures, in one tested place |
| Forgiving diagnostics with severities | Warnings ignore a line, errors leave it unparsed, and the build always continues |
| A stale marker on the frame's source | Appears when the frame's shapes are edited by hand; regenerating replaces the shapes as one gesture |
| Mermaid import | Paste, convert, then edit as shapes |
| More families | Wireframe, infographic, gitgraph, gantt, sankey, chart — the six that currently report an unsupported family |

There is no `shapes → source` serializer, and there will not be one. Source is an input; the frame keeps the text it was generated from.

## What "done" means here

Same contract as v1: every row above gets a named test that asserts paint or behaviour, and the traceability table in [`v1.md`](./v1.md) grows to cover it. Nothing moves into v1.5 to escape a hard test.
