# Kiyora v2

v2 is where Kiyora stops being an offline-only toy and starts being a product. Everything here needs the server that `apps/web` already runs, which is why v1 refused a static export.

The offline promise holds at every step: **the editor keeps working with the network off.** Everything in v2 is additive, and each row is designed so the local path still works without it.

## Identity and documents

| Item | Notes |
| --- | --- |
| Many boards | A board list, rename, duplicate, delete |
| Accounts | Sign in, and an editor that stays fully usable signed out |
| Cloud sync | The same board in more than one browser, with a revision check instead of a last-write-wins clobber |
| Sharing | A read-only link to a board |
| Comments and mentions | Anchored threads |
| Real-time collaboration | Only after the above three are stable; this is the row that can slip forever without blocking anything else |

## Assistant and agents

| Item | Notes |
| --- | --- |
| Assistant panel | A prompt draws on the board, and the result is editable shapes, not a picture |
| Generated images | |
| MCP server | The board as a tool surface for coding agents |
| Deterministic serializer | The one place `shapes → source` finally exists: generated boards must reopen as editable code, byte for byte |

That serializer is the only reason to ever build one, and it is the reason the v1 position — no serializer — is a position about *hand edits*, not about generation.

## Files and imports

| Item | Notes |
| --- | --- |
| Importers | Mermaid, Excalidraw, tldraw, eraser.io, CSV and TSV to tables, SVG |
| PDF export | Optional, and the lowest-priority row in this document |
| The remaining families | Whatever v1.5 has not already added |

## Explicitly never

| Not building | Why |
| --- | --- |
| Billing | There is nothing to buy |
| A workspace or seat model | One person's boards do not need an org chart |
| A proprietary image library | The reference's is licensed against exactly this product |

## What "done" means here

Unchanged: every row gets a named test that asserts paint or behaviour. v2 rows are the first ones where a test may legitimately need a network double, and the offline guard must stay green — a v2 feature that breaks offline is a bug, not a trade-off.
