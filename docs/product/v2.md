# Kiyora v2

v2 is where a board stops being alone in one browser: a library of boards, an optional account, two copies of a board kept honest by a revision check, and a link that shows one read-only.

**Status: planned, not built.** Every row below names the test that will prove it; none of those tests exists yet. Nothing here is a claim about shipped behaviour, and [`architecture.md`](../architecture.md) is updated as each cut lands rather than in advance.

**Scope of this round: V2.0 and V2.1.** The other three cuts are recorded in [Deferred, decided](#deferred-decided) with the reasoning, so the next session starts from a decision and not from a blank page.

The offline promise holds at every step: **the editor and the library keep working with the network off.** Every row is additive, and a v2 feature that breaks offline is a bug, not a trade-off.

## Definition of done

Three conditions, all mechanical.

**1. Two new acceptance journeys pass in CI.**

`apps/web/tests/e2e/journey-library.spec.ts`:

> open the library → create a board → draw a rectangle → reload → the board is in the list and paints → rename it → duplicate it → edit the copy → both titles and both boards differ → delete the copy → open the original by its address → draw while every request is aborted

`apps/web/tests/e2e/journey-sync.spec.ts`:

> sign in → link a board → a second browser context lists it and opens it → both contexts edit → the second syncs → the first syncs into a conflict → keep mine → share the board → a signed-out third context opens the link and cannot edit → revoke the link → the address stops working → edit offline in the first context → reconnect → the edit arrives

**2. Every capability below is proven by a named test** that asserts paint or behaviour. An element count proves nothing. Where a row can only be proven against a network double, the row says so, and the untested remainder is named in [Risks](#risks) rather than covered up.

**3. Every gate is green.** `check`, `check-types`, `test`, `test:e2e`, `check-budgets`, `check-icons`. The payload and first-paint ceilings stay where v1.5 left them. The offline guard stops being a per-spec copy: it becomes a fixture **every spec inherits**, and only the specs that test sync opt out. The e2e run gains a third project that drives the real server against a real Postgres, so the sync contract is proven and not only mocked.

## Cut V2.0 — the library

The library needs no server. It is the first cut because sync has nothing to sync until a board has an id in a library, and because it can ship on its own.

### Foundations (P0)

| Item | Notes |
| --- | --- |
| Plural keys | `kiyora:boards:<id>`, `kiyora:boards:<id>:snapshot`, `kiyora:boards:<id>:quarantine`. The singular `kiyora:board:snapshot` would otherwise read as a board named "snapshot" |
| The library record | `kiyora:library`: id, title, updatedAt, linked, tooLarge, preview. The list orders by `updatedAt` and never opens a payload |
| The record is rebuildable | Its content derives from the `kiyora:boards:` prefix. Losing it is a repair, not a data loss |
| Identity is real | `crypto.randomUUID()` in the browser; `createdAt` and `updatedAt` stop being frozen fixture values |
| `updatedAt` is not undoable | Autosave writes it from an injected clock, and history snapshots exclude it the way they exclude the camera |
| One upgrade | IndexedDB moves to version 2: adopt the legacy `kiyora:board` as the first board, move its snapshot beside it, remove the legacy keys, leave the out-of-line keys and the store name untouched |
| The storage port names a board | `BoardStorage` becomes a library-shaped port; autosave is bound to one board id |

### The library (P1)

| Item | Notes |
| --- | --- |
| Two routes | `/` lists, `/b/<id>` opens. A board's address is the board's id, and nothing else is encoded in the URL |
| Rename | Inline in the list and in the editor's title; the record and the payload's `title` cannot disagree because the payload is written first |
| Duplicate | A new id, a new payload, and an edit to one never reaches the other |
| Delete | Hard, with a confirm. A linked board's confirm names both copies |
| A new board is empty | No starter diagram. `starterBoard()` becomes a test fixture and nothing else |
| Previews | One small SVG per board, regenerated on save through `paintBoard` + `projectBoard`, capped, omitted rather than truncated when it would exceed the cap |
| Import a board file | `openBoardFile` adds a board to the library instead of replacing the open one. The file's id is kept unless the library already holds it, in which case the import is a new id |

### Isolation (P2)

| Item | Notes |
| --- | --- |
| Presence per board | `BroadcastChannel('kiyora:board:<id>')`. Today one global channel makes the older tab of another board suppress this tab's autosave |
| Clipboard per board | The relay message carries the board id; a paste into another board is refused rather than pasted into the wrong document |
| Offline by default | The guard becomes one fixture that aborts every non-localhost request for every spec; a sync spec opts out explicitly, per spec |
| One seeding helper | The e2e suite seeds boards through one helper, so the thirteen specs that spell the storage layout stop doing it |
| `file-controls.tsx` splits | It is at 342/400 lines and is where import lands. The import action moves out before the change |

## Cut V2.1 — accounts, sync, sharing

Everything here needs a server. The local copy stays the only editable one.

### The server (S0)

| Item | Notes |
| --- | --- |
| Deployment | Vercel, plus a managed Postgres (Neon or Supabase). The database is not self-hosted |
| Schema | Drizzle, migrations committed. `board`: client id as the primary key, `owner_id`, `revision`, `title`, `payload`, `bytes`, `preview_svg`, `created_at`, `updated_at`, `payload_hash`. `share_link`: `token`, `board_id`, `created_at`, `revoked_at`. Better Auth's four tables come from its generator |
| The server validates | Every accepted payload passes `boardSchema`, and its `schemaVersion` must be current. Migration stays the client's job |
| Columns are a cache | `title`, `updatedAt`, `bytes`, `preview_svg` and `payload_hash` are extracted from the payload the server just validated, so listing never parses a board |
| Accounts | Better Auth: Google and GitHub. No magic links. `emailAndPassword` exists only when `AUTH_DEV_CREDENTIALS` names a non-production environment, and a production build refuses to start if it is set |
| Signing out | Local copies stay, sync stops, and nothing is deleted remotely. There is no unlink in this round: deleting a linked board is the only exit |
| The editor stays signed out | The library and the canvas never require a session, and a signed-out client makes no request to `/api/` |

### Sync (S1)

| Item | Notes |
| --- | --- |
| `packages/sync` | A DOM-free, transport-agnostic reconciler with a `SyncTransport` port. It depends on `model` for the board type, never on `editor` or the DOM, and it owns the state machine: local, pending, syncing, synced, conflict, too large, signed out, error |
| Linking is explicit | Signing in uploads nothing. "Sync this board" creates the remote copy with `baseRevision: null`; linking is the only path from local to remote |
| Revision check | The server accepts a write only when `baseRevision` equals the stored revision; otherwise `409` carries the remote revision and payload |
| Retry is safe | A retry whose payload hash equals the stored one returns `200` with the current revision instead of a phantom conflict |
| The sync limit | 4 MiB of serialized payload, because Vercel caps a function body at 4.5 MB in both directions. Over the limit, the board stays local with a visible state; nothing is truncated and nothing retries forever |
| A second browser | Signed in, the library shows **Your boards** — remote copies not present locally. Open downloads the payload into the library and links it; nothing is mirrored unasked |
| Sync is a background reconciler | Triggered after an autosave, on reconnect and on visibility, never blocking an edit, and never a second editor |

### Conflict (S2)

| Item | Notes |
| --- | --- |
| Three resolutions | Keep mine (upload at the remote revision), take theirs (replace the local copy), or duplicate mine (a new board that carries your bytes, uploaded as a new board) |
| Taking theirs keeps yours | The replaced copy becomes the board's recovery snapshot and a `.kyr.json` download before anything is overwritten |
| The conflict survives a reload | The marker and the remote revision live with the local board; the remote payload is fetched on demand and cached until resolved |

### Sharing (S3)

| Item | Notes |
| --- | --- |
| One link per board | `/s/<token>`, 128-bit random, unlisted, revocable. Regenerating revokes the old token |
| Read-only, signed out | The same renderer with no editing chrome, no autosave, no presence and no session requirement |
| Latest committed revision | Served on page load. No realtime, and the page says nothing about being live |
| Sharing needs a remote copy | A local-only board has nothing to share, so the action is absent until the board is linked |

## Risks

Recorded now, because a plan that hides them is the failure mode v1.5's audit named.

- **The sync contract is proven by a real server and Postgres, at a cost.** The `server` project needs a database in CI (a service container, or a Neon branch) and applies the migrations before it runs. It is the slow project, so it runs once per task rather than per file.
- **OAuth cannot be walked end to end in CI.** Dev credentials are the proxy, and the real callback is a manual smoke test on the hosted deploy.
- **The 4.5 MB function limit sets a 4 MiB sync limit.** A board that is legal locally can be too large to sync; the state is visible, but the capability is absent for image-heavy boards.
- **The library record can drift from the payloads.** It is a cache, so the repair path is part of the work and not a later fix.
- **Thirteen specs change at once** when the seeding helper lands. It is one ticket and it is deliberately before sync.
- **Drizzle migrations enter the deploy path.** The plan is `drizzle-kit generate` committed, applied before the app serves traffic, with the build failing rather than starting on a schema mismatch.

## Corrections to the first draft

Recorded rather than quietly reworded.

- **"Everything here needs the server"** — false for many boards, which is a local storage change, and false for the assistant's contract, which needs one proxy route. Only accounts, sync, sharing, comments and collab need a server.
- **The first draft was one flat table per area**, with no cuts, no ordering and no tests. It listed six identity rows before the prerequisite they all share: a board that has an id.
- **"Comments and mentions" sat next to sharing as if adjacent** — a thread needs an account and a board someone else can open, so it follows both.
- **"The remaining families" read as one row** — six Mermaid grammars, four of which are layout engines. Two of the six land on shapes that already exist.
- **The draft implied a server-rendered PDF** by listing it beside export, and did not say that Vercel's body limit bounds what can sync.
